Ejercicios de Transformación DER a Modelo Físico

Ejercicio 1: Sistema de Biblioteca

DER Original:

    LIBRO (1:N) escrito_por AUTOR
    LIBRO (N:M) prestado_a USUARIO
    USUARIO (1:N) tiene MULTA
    
    Atributos Libro: ID, Título, ISBN, Año_Publicación
    Atributos Autor: ID, Nombre, Nacionalidad
    Atributos Usuario: ID, Nombre, Email, Teléfono
    Atributos Multa: ID, Fecha, Monto
    Atributos Préstamo: Fecha_Préstamo, Fecha_Devolución

Transformación a Modelo Físico:

    CREATE TABLE AUTORES (
        ID_AUTOR INT PRIMARY KEY,
        NOMBRE VARCHAR(100),
        NACIONALIDAD VARCHAR(50)
    );
    
    CREATE TABLE LIBROS (
        ID_LIBRO INT PRIMARY KEY,
        TITULO VARCHAR(200),
        ISBN VARCHAR(13),
        ANIO_PUBLICACION INT,
        ID_AUTOR INT,
        FOREIGN KEY (ID_AUTOR) REFERENCES AUTORES(ID_AUTOR)
    );
    
    CREATE TABLE USUARIOS (
        ID_USUARIO INT PRIMARY KEY,
        NOMBRE VARCHAR(100),
        EMAIL VARCHAR(100),
        TELEFONO VARCHAR(15)
    );
    
    CREATE TABLE MULTAS (
        ID_MULTA INT PRIMARY KEY,
        ID_USUARIO INT,
        FECHA DATE,
        MONTO DECIMAL(10,2),
        FOREIGN KEY (ID_USUARIO) REFERENCES USUARIOS(ID_USUARIO)
    );
    
    CREATE TABLE PRESTAMOS (
        ID_LIBRO INT,
        ID_USUARIO INT,
        FECHA_PRESTAMO DATE,
        FECHA_DEVOLUCION DATE,
        PRIMARY KEY (ID_LIBRO, ID_USUARIO, FECHA_PRESTAMO),
        FOREIGN KEY (ID_LIBRO) REFERENCES LIBROS(ID_LIBRO),
        FOREIGN KEY (ID_USUARIO) REFERENCES USUARIOS(ID_USUARIO)
    );

Ejercicio 2: Sistema de Gestión de Hospital

DER Original:

    MEDICO (N:M) atiende PACIENTE
    PACIENTE (1:N) tiene HISTORIAL_MEDICO
    MEDICO (N:1) pertenece_a DEPARTAMENTO
    PACIENTE (N:M) toma MEDICAMENTO
    
    Atributos Médico: ID, Nombre, Especialidad, Número_Colegiado
    Atributos Paciente: ID, Nombre, Fecha_Nacimiento, DNI
    Atributos Departamento: ID, Nombre, Planta
    Atributos Historial_Médico: ID, Fecha, Diagnóstico
    Atributos Medicamento: ID, Nombre, Dosis, Descripción
    Atributos Consulta: Fecha, Hora, Motivo

Transformación a Modelo Físico:

    CREATE TABLE DEPARTAMENTOS (
        ID_DEPARTAMENTO INT PRIMARY KEY,
        NOMBRE VARCHAR(100),
        PLANTA INT
    );
    
    CREATE TABLE MEDICOS (
        ID_MEDICO INT PRIMARY KEY,
        NOMBRE VARCHAR(100),
        ESPECIALIDAD VARCHAR(50),
        NUMERO_COLEGIADO VARCHAR(20),
        ID_DEPARTAMENTO INT,
        FOREIGN KEY (ID_DEPARTAMENTO) REFERENCES DEPARTAMENTOS(ID_DEPARTAMENTO)
    );
    
    CREATE TABLE PACIENTES (
        ID_PACIENTE INT PRIMARY KEY,
        NOMBRE VARCHAR(100),
        FECHA_NACIMIENTO DATE,
        DNI VARCHAR(10)
    );
    
    CREATE TABLE HISTORIALES_MEDICOS (
        ID_HISTORIAL INT PRIMARY KEY,
        ID_PACIENTE INT,
        FECHA DATE,
        DIAGNOSTICO TEXT,
        FOREIGN KEY (ID_PACIENTE) REFERENCES PACIENTES(ID_PACIENTE)
    );
    
    CREATE TABLE MEDICAMENTOS (
        ID_MEDICAMENTO INT PRIMARY KEY,
        NOMBRE VARCHAR(100),
        DOSIS VARCHAR(50),
        DESCRIPCION TEXT
    );
    
    CREATE TABLE CONSULTAS (
        ID_MEDICO INT,
        ID_PACIENTE INT,
        FECHA DATE,
        HORA TIME,
        MOTIVO TEXT,
        PRIMARY KEY (ID_MEDICO, ID_PACIENTE, FECHA, HORA),
        FOREIGN KEY (ID_MEDICO) REFERENCES MEDICOS(ID_MEDICO),
        FOREIGN KEY (ID_PACIENTE) REFERENCES PACIENTES(ID_PACIENTE)
    );
    
    CREATE TABLE PRESCRIPCIONES (
        ID_PACIENTE INT,
        ID_MEDICAMENTO INT,
        FECHA_INICIO DATE,
        FECHA_FIN DATE,
        PRIMARY KEY (ID_PACIENTE, ID_MEDICAMENTO, FECHA_INICIO),
        FOREIGN KEY (ID_PACIENTE) REFERENCES PACIENTES(ID_PACIENTE),
        FOREIGN KEY (ID_MEDICAMENTO) REFERENCES MEDICAMENTOS(ID_MEDICAMENTO)
    );

Notas sobre la Transformación:

  • Las relaciones 1:N se implementan mediante claves foráneas en la tabla del lado N
  • Las relaciones N:M requieren una tabla intermedia con las claves de ambas entidades
  • Se han seguido las convenciones de nombres (PK_, FK_, etc.)
  • Se han elegido tipos de datos apropiados para cada atributo
  • Se han incluido las restricciones de clave primaria y foránea necesarias
