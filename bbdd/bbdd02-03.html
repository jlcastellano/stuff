2.3. Diagrama Entidad/Relación Extendido

Características Adicionales del Modelo Extendido

1. Especialización/Generalización

Permite representar jerarquías entre entidades.

Tipos de Especialización:

  • Total: Toda entidad padre debe pertenecer a alguna subclase
  • Parcial: Puede haber entidades padre sin subclase
  • Exclusiva: Una entidad solo puede pertenecer a una subclase
  • Solapada: Una entidad puede pertenecer a varias subclases
                [EMPLEADO]

                    ↓

                [TÉCNICO] [ADMINISTRATIVO] [DIRECTIVO]

2. Agregación

Representa una relación "es parte de" entre entidades.

Ejemplo: Un departamento tiene empleados y proyectos 
                    [DEPARTAMENTO]◇━━━[EMPLEADO]

                          ◇

                    [PROYECTO]

3. Atributos Compuestos

Tipo Ejemplo
Dirección - Calle
- Número
- Ciudad
- Código Postal
Nombre Completo - Nombre
- Apellido1
- Apellido2

4. Restricciones de Integridad Avanzadas

  • Restricciones de Participación
  • Restricciones de Cobertura
  • Dependencias de Existencia
  • Restricciones de Rol
Las restricciones ayudan a mantener la integridad y consistencia de los datos.

5. Entidades Asociativas

Permiten tratar una relación como si fuera una entidad.

Ejemplo: Matrícula de Estudiantes en Cursos

                    [ESTUDIANTE]──[MATRÍCULA]──[CURSO]

                                    │

                                [Fecha]

                                [Calificación]

6. Ejemplo Completo de DER Extendido

                [PERSONA]

                    ↓ (T,E)

                [CLIENTE]────[PEDIDO]────[PRODUCTO]

                    │          │            │

                [Dirección]  [Fecha]     [Stock]

                [Teléfono]   [Total]     [Precio]

Elementos del ejemplo:

  • Especialización total y exclusiva de PERSONA en CLIENTE
  • Relaciones N:M entre CLIENTE-PEDIDO y PEDIDO-PRODUCTO
  • Atributos simples y compuestos
  • Cardinalidades especificadas

Ventajas del Modelo Extendido

  • Mayor capacidad de representación
  • Mejor expresión de restricciones
  • Modelado más preciso
  • Facilita la transición al modelo relacional

Consideraciones Importantes

  • No abusar de las características extendidas si no son necesarias
  • Mantener la claridad del diagrama
  • Documentar las restricciones complejas
  • Validar el modelo con los usuarios
