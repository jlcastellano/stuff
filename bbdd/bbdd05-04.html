Transacciones en SQL

Definición de Transacción

Una transacción es una unidad de trabajo que agrupa una secuencia de una o más operaciones SQL que se ejecutan como una única unidad atómica e indivisible. Esto significa que o todas las operaciones se completan con éxito, o ninguna de ellas tiene efecto sobre la base de datos.

Propiedades ACID

1. Atomicidad (Atomicity)

Una transacción se ejecuta completamente o no se ejecuta en absoluto. No hay ejecuciones parciales.

Ejemplo: En una transferencia bancaria, o se debita una cuenta y se acredita la otra, o no se realiza ningún cambio.

2. Consistencia (Consistency)

La base de datos debe pasar de un estado válido a otro estado válido. Se mantienen todas las reglas y restricciones.

Ejemplo: El total de débitos debe igualar al total de créditos después de una transferencia.

3. Aislamiento (Isolation)

Las transacciones se ejecutan de manera aislada unas de otras, sin interferencias entre ellas.

Ejemplo: Dos transferencias simultáneas no deben interferir entre sí.

4. Durabilidad (Durability)

Una vez que una transacción se confirma (commit), los cambios son permanentes y sobreviven a fallos del sistema.

Ejemplo: Una transferencia confirmada persiste incluso si hay un corte de energía.

Estructura de una Transacción

-- Inicio de la transacción
START TRANSACTION;

    -- Operaciones de la transacción
    UPDATE cuenta SET saldo = saldo - 1000 
    WHERE id = 1;
    
    UPDATE cuenta SET saldo = saldo + 1000 
    WHERE id = 2;

-- Si todo está bien
COMMIT;

-- Si hay error
ROLLBACK;

Estados de una Transacción

Activa → [Parcialmente Confirmada] → Confirmada (Committed)
   ↓                                    ↑
   └→ [Fallida] → Abortada → Terminada →┘
  • Activa: Durante la ejecución de operaciones
  • Parcialmente Confirmada: Después de la última operación
  • Fallida: Cuando se detecta que no puede continuar
  • Abortada: Después de deshacer cambios (rollback)
  • Confirmada: Después de asegurar durabilidad (commit)

Ejemplos Prácticos

1. Transferencia Bancaria

START TRANSACTION;

    -- Verificar saldo suficiente
    SELECT @saldo := saldo FROM cuentas 
    WHERE id = 1 FOR UPDATE;
    
    IF @saldo >= 1000 THEN
        -- Debitar cuenta origen
        UPDATE cuentas 
        SET saldo = saldo - 1000 
        WHERE id = 1;
        
        -- Acreditar cuenta destino
        UPDATE cuentas 
        SET saldo = saldo + 1000 
        WHERE id = 2;
        
        COMMIT;
    ELSE
        ROLLBACK;
    END IF;

2. Proceso de Compra

START TRANSACTION;

    -- Insertar pedido
    INSERT INTO pedidos (cliente_id, fecha)
    VALUES (1, NOW());
    
    -- Obtener ID del pedido
    SET @pedido_id = LAST_INSERT_ID();
    
    -- Insertar detalles
    INSERT INTO detalles_pedido 
        (pedido_id, producto_id, cantidad)
    VALUES 
        (@pedido_id, 101, 2),
        (@pedido_id, 102, 1);
    
    -- Actualizar inventario
    UPDATE productos 
    SET stock = stock - 2 
    WHERE id = 101;
    
    UPDATE productos 
    SET stock = stock - 1 
    WHERE id = 102;

COMMIT;

Puntos de Guardado (Savepoints)

Permiten crear puntos de control dentro de una transacción.

START TRANSACTION;

    INSERT INTO tabla1 VALUES (1);
    SAVEPOINT punto1;

    INSERT INTO tabla2 VALUES (2);
    SAVEPOINT punto2;

    -- Si hay error después de punto2
    ROLLBACK TO punto2;

    -- O volver más atrás
    ROLLBACK TO punto1;

COMMIT;

Buenas Prácticas

  • Mantener las transacciones lo más cortas posible
  • Evitar interacción con el usuario durante una transacción
  • Manejar adecuadamente los errores y excepciones
  • Considerar el nivel de aislamiento apropiado
  • Usar savepoints para transacciones complejas
  • Probar el comportamiento con concurrencia
