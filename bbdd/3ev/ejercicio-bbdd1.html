Ejercicio 1: Sistema de Cálculo de Comisiones (30 puntos)

Descripción del Problema:

Una empresa de ventas necesita automatizar el cálculo de comisiones para sus vendedores. Se requiere crear un procedimiento almacenado que calcule las comisiones mensuales basándose en las ventas totales de cada vendedor.

Requerimientos Específicos:

  1. Crear un procedimiento almacenado llamado sp_calcular_comisiones
  2. El procedimiento debe aceptar dos parámetros:
    • @mes (INT): Mes para el cálculo
    • @año (INT): Año para el cálculo
  3. La comisión debe ser el 5% del total de ventas del vendedor en el mes especificado
  4. Implementar manejo de transacciones para garantizar la integridad de los datos
  5. Actualizar la tabla de vendedores con las comisiones calculadas

Estructura de Tablas:

CREATE TABLE vendedores (
    id_vendedor INT PRIMARY KEY,
    nombre VARCHAR(100),
    comision DECIMAL(10,2)
)

CREATE TABLE ventas (
    id_venta INT PRIMARY KEY,
    id_vendedor INT,
    fecha_venta DATE,
    monto_venta DECIMAL(10,2)
)

Criterios de Evaluación:

Criterio Puntuación
Correcta declaración del procedimiento almacenado 5 puntos
Implementación correcta del cálculo de comisiones 8 puntos
Manejo adecuado de transacciones 7 puntos
Correcto uso de los parámetros @mes y @año 5 puntos
Actualización correcta de la tabla vendedores 5 puntos

Notas Adicionales:

  • El código debe estar correctamente indentado y comentado
  • Se evaluará el manejo de errores implementado
  • La solución debe ser eficiente en términos de rendimiento
  • Se debe considerar la posibilidad de valores NULL en las ventas

Ejercicio 2: Procedimiento de Cierre Mensual (40 puntos)

Descripción del Problema:

Se requiere implementar un procedimiento almacenado que realice el cierre mensual de ventas, calculando totales y actualizando las estadísticas del mes en una tabla de resumen.

Requerimientos Específicos:

  1. Crear un procedimiento almacenado llamado sp_cierre_mensual
  2. El procedimiento debe aceptar dos parámetros:
    • @mes (INT): Mes del cierre
    • @año (INT): Año del cierre
  3. Debe calcular y almacenar:
    • Total de ventas del mes
    • Total de productos vendidos
    • Identificar al mejor vendedor del mes
  4. Implementar manejo de transacciones
  5. Generar registro en la tabla resumen_mensual

Estructura de Tablas:

CREATE TABLE resumen_mensual (
    id_resumen INT PRIMARY KEY IDENTITY(1,1),
    mes INT,
    año INT,
    total_ventas DECIMAL(12,2),
    total_productos_vendidos INT,
    mejor_vendedor INT
)

CREATE TABLE detalles_venta (
    id_detalle INT PRIMARY KEY,
    id_venta INT,
    cantidad INT,
    precio_unitario DECIMAL(10,2)
)

Criterios de Evaluación - Ejercicio 2:

Criterio Puntuación
Correcta declaración del procedimiento 5 puntos
Cálculo correcto de totales 10 puntos
Identificación correcta del mejor vendedor 8 puntos
Manejo adecuado de transacciones 7 puntos
Inserción correcta en resumen_mensual 10 puntos

Notas Adicionales:

  • Considerar la posibilidad de registros duplicados
  • Validar la existencia de datos para el mes y año especificados
  • Implementar manejo de errores robusto
  • Optimizar las consultas para mejor rendimiento

Ejercicio 3: Cursor para Actualización Masiva de Precios (30 puntos)

Descripción del Problema:

Se necesita implementar un mecanismo para actualizar los precios de los productos de forma masiva, aplicando diferentes porcentajes de incremento según la categoría del producto utilizando un cursor.

Requerimientos Específicos:

  1. Crear un cursor que recorra la tabla de productos
  2. Aplicar los siguientes incrementos:
    • Electrónica: 10% de incremento
    • Ropa: 5% de incremento
    • Otras categorías: 3% de incremento
  3. Actualizar los precios de manera individual para cada producto
  4. Implementar el correcto manejo del cursor (apertura, recorrido y liberación)
  5. Manejar las variables necesarias para el procesamiento

Estructura de Tablas:

CREATE TABLE productos (
    id_producto INT PRIMARY KEY,
    nombre VARCHAR(100),
    categoria VARCHAR(50),
    precio DECIMAL(10,2)
)

Criterios de Evaluación - Ejercicio 3:

Criterio Puntuación
Declaración correcta del cursor y variables 6 puntos
Implementación correcta del CASE para incrementos 8 puntos
Manejo adecuado del ciclo WHILE 6 puntos
Correcta actualización de precios 5 puntos
Liberación apropiada de recursos 5 puntos

Notas Adicionales:

  • El cursor debe estar correctamente cerrado y liberado
  • Considerar el rendimiento al procesar grandes volúmenes de datos
  • Validar que los nuevos precios sean coherentes
  • Documentar el código adecuadamente
