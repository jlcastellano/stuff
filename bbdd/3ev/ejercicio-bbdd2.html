Ejercicio 4: Sistema de Gestión de Inventario (30 puntos)

Descripción del Problema:

Desarrollar un trigger que mantenga actualizado automáticamente el inventario cuando se realizan ventas y que evite ventas cuando no hay stock suficiente.

Requerimientos Específicos:

  1. Crear un trigger AFTER INSERT en la tabla detalles_venta
  2. Verificar stock disponible antes de permitir la venta
  3. Actualizar automáticamente el stock en la tabla productos
  4. Mantener un registro de movimientos de inventario
  5. Implementar rollback si no hay stock suficiente

Estructura de Tablas Adicional:

CREATE TABLE movimientos_inventario (
    id_movimiento INT PRIMARY KEY AUTO_INCREMENT,
    id_producto INT,
    tipo_movimiento ENUM('ENTRADA', 'SALIDA'),
    cantidad INT,
    fecha_movimiento DATETIME,
    usuario VARCHAR(50)
)

Criterios de Evaluación:

Criterio Puntuación
Implementación correcta del trigger 8 puntos
Validación de stock 7 puntos
Registro de movimientos 5 puntos
Manejo de errores 5 puntos
Rollback implementado 5 puntos

Ejercicio 5: Sistema de Fidelización de Clientes (35 puntos)

Descripción del Problema:

Crear un sistema de puntos de fidelización que calcule y actualice automáticamente los puntos de los clientes basándose en sus compras.

Estructura de Tablas:

CREATE TABLE clientes (
    id_cliente INT PRIMARY KEY,
    nombre VARCHAR(100),
    nivel_fidelidad VARCHAR(20),
    puntos_acumulados INT DEFAULT 0
);

CREATE TABLE niveles_fidelidad (
    nivel VARCHAR(20) PRIMARY KEY,
    puntos_minimos INT,
    porcentaje_beneficio DECIMAL(5,2)
);

Requerimientos:

  1. Función que calcule puntos por compra (1 punto por cada $10)
  2. Procedimiento que actualice nivel de fidelidad
  3. Trigger que actualice puntos después de cada venta
  4. Procedimiento de canje de puntos

Criterios de Evaluación:

Criterio Puntuación
Función de cálculo de puntos 8 puntos
Procedimiento de actualización de nivel 10 puntos
Trigger de actualización 9 puntos
Procedimiento de canje 8 puntos

Ejercicio 6: Gestión de Pedidos y Stock Automático (40 puntos)

Descripción del Problema:

Implementar un sistema automático de gestión de inventario que monitoree los niveles de stock y genere pedidos automáticos cuando sea necesario, considerando tiempos de entrega y niveles óptimos de inventario.

Requerimientos Específicos:

  1. Crear un trigger AFTER UPDATE en la tabla productos que monitoree el stock
  2. Implementar una función que calcule la necesidad de pedido basada en:
    • Stock actual vs. stock mínimo
    • Tendencia de ventas del último mes
    • Tiempo promedio de entrega
  3. Crear un procedimiento almacenado que:
    • Verifique productos bajo mínimos
    • Genere pedidos automáticos
    • Actualice el estado de los pedidos
  4. Implementar un sistema de notificaciones para pedidos urgentes

Estructura de Tablas Adicional:

CREATE TABLE configuracion_stock (
    id_producto INT PRIMARY KEY,
    stock_minimo INT,
    stock_optimo INT,
    tiempo_entrega_dias INT,
    punto_pedido INT,
    FOREIGN KEY (id_producto) REFERENCES productos(id_producto)
);

CREATE TABLE historial_ventas_diarias (
    id_historial INT PRIMARY KEY AUTO_INCREMENT,
    id_producto INT,
    fecha DATE,
    unidades_vendidas INT,
    FOREIGN KEY (id_producto) REFERENCES productos(id_producto)
);

CREATE TABLE notificaciones_stock (
    id_notificacion INT PRIMARY KEY AUTO_INCREMENT,
    id_producto INT,
    tipo_notificacion ENUM('BAJO_MINIMO', 'PEDIDO_GENERADO', 'PEDIDO_URGENTE'),
    mensaje TEXT,
    fecha_notificacion DATETIME DEFAULT CURRENT_TIMESTAMP,
    estado ENUM('PENDIENTE', 'PROCESADA') DEFAULT 'PENDIENTE',
    FOREIGN KEY (id_producto) REFERENCES productos(id_producto)
);

Criterios de Evaluación:

Criterio Puntuación
Implementación del trigger de monitoreo 8 puntos
Función de cálculo de necesidades 10 puntos
Procedimiento de gestión de pedidos 12 puntos
Sistema de notificaciones 5 puntos
Manejo de errores y transacciones 5 puntos

Ejercicio 7: Sistema de Auditoría y Control de Acceso (35 puntos)

Descripción del Problema:

Desarrollar un sistema completo de auditoría y control de acceso que registre todas las operaciones críticas y gestione los permisos de usuarios según su nivel de acceso.

Requerimientos Específicos:

  1. Implementar triggers de auditoría para:
    • Cambios en precios de productos
    • Modificaciones de comisiones
    • Operaciones en ventas
    • Cambios en niveles de acceso
  2. Crear procedimientos para control de acceso que:
    • Validen el nivel de acceso del usuario
    • Registren intentos de acceso no autorizado
    • Gestionen la elevación temporal de privilegios
  3. Desarrollar funciones de verificación de permisos

Estructura de Tablas Adicional:

CREATE TABLE usuarios_sistema (
    id_usuario INT PRIMARY KEY AUTO_INCREMENT,
    nombre_usuario VARCHAR(50),
    nivel_acceso ENUM('BASICO', 'SUPERVISOR', 'ADMINISTRADOR'),
    estado ENUM('ACTIVO', 'INACTIVO', 'BLOQUEADO')
);

CREATE TABLE permisos_especiales (
    id_permiso INT PRIMARY KEY AUTO_INCREMENT,
    id_usuario INT,
    tipo_permiso VARCHAR(50),
    fecha_inicio DATETIME,
    fecha_fin DATETIME,
    autorizado_por INT,
    FOREIGN KEY (id_usuario) REFERENCES usuarios_sistema(id_usuario)
);

CREATE TABLE log_accesos (
    id_log INT PRIMARY KEY AUTO_INCREMENT,
    id_usuario INT,
    tipo_operacion VARCHAR(50),
    fecha_hora DATETIME,
    resultado ENUM('EXITOSO', 'DENEGADO'),
    detalles JSON,
    FOREIGN KEY (id_usuario) REFERENCES usuarios_sistema(id_usuario)
);

Criterios de Evaluación:

Criterio Puntuación
Implementación de triggers de auditoría 10 puntos
Sistema de control de acceso 8 puntos
Funciones de verificación 7 puntos
Gestión de permisos especiales 5 puntos
Registro de auditoría 5 puntos

Ejercicio 8: Sistema de Reportes Dinámicos con Análisis (40 puntos)

Descripción del Problema:

Crear un sistema flexible de generación de reportes que permita análisis dinámicos de datos, incluyendo tendencias, comparativas y proyecciones.

Requerimientos Específicos:

  1. Implementar un procedimiento principal que:
    • Interprete configuraciones JSON de reportes
    • Genere consultas dinámicas
    • Aplique filtros y agregaciones
  2. Crear funciones de análisis para:
    • Cálculo de tendencias
    • Comparativas interanuales
    • Proyecciones de ventas
    • Análisis de rendimiento
  3. Desarrollar cursores para procesamiento de datos agregados
  4. Implementar cache de resultados para reportes frecuentes

Estructura de Tablas Adicional:

CREATE TABLE plantillas_reporte (
    id_plantilla INT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(100),
    descripcion TEXT,
    configuracion JSON,
    tipo_analisis ENUM('TENDENCIA', 'COMPARATIVA', 'PROYECCION', 'RENDIMIENTO')
);

CREATE TABLE cache_reportes (
    id_cache INT PRIMARY KEY AUTO_INCREMENT,
    hash_configuracion VARCHAR(64),
    datos JSON,
    fecha_generacion DATETIME,
    fecha_expiracion DATETIME
);

CREATE TABLE metricas_rendimiento (
    id_metrica INT PRIMARY KEY AUTO_INCREMENT,
    nombre_metrica VARCHAR(100),
    formula TEXT,
    unidad_medida VARCHAR(20),
    categoria VARCHAR(50)
);

Criterios de Evaluación:

Criterio Puntuación
Generación dinámica de consultas 10 puntos
Funciones de análisis 10 puntos
Implementación de cursores 8 puntos
Sistema de cache 7 puntos
Manejo de errores y optimización 5 puntos
