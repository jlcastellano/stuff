6. Niveles de aislamiento

Para evitar que sucedan los problemas de acceso concurrente que hemos comentado en el punto anterior podemos establecer diferentes niveles de aislamiento.

Read Uncommited

En este nivel no se realiza ningún bloqueo, por lo tanto, permite que sucedan los tres problemas.

Problemas permitidos:

  • Dirty Read
  • Non-repeatable Read
  • Phantom Read

Read Commited

En este caso los datos leídos por una transacción pueden ser modificados por otras transacciones, por lo tanto, se pueden dar los problemas Phantom Read y Non Repeateable Read.

Problemas permitidos:

  • Non-repeatable Read
  • Phantom Read

Repeateable Read

En este nivel ningún registro leído con un SELECT puede ser modificado en otra transacción, por lo tanto, sólo puede suceder el problema del Phantom Read.

Problemas permitidos:

  • Phantom Read

Serializable

En este caso las transacciones se ejecutan unas detrás de otras, sin que exista la posibilidad de concurrencia.

Problemas permitidos:

  • Ninguno

Nota sobre InnoDB

El nivel de aislamiento que utiliza InnoDB por defecto es Repeateable Read.
