Niveles de Aislamiento en Transacciones SQL

Problemas de Concurrencia

1. Lecturas Sucias (Dirty Reads)

Ocurre cuando una transacción lee datos que no han sido confirmados por otra transacción.

Ejemplo:
  1. Transacción A actualiza el saldo de una cuenta
  2. Transacción B lee el nuevo saldo antes del COMMIT
  3. Transacción A hace ROLLBACK
  4. Transacción B tiene datos incorrectos

2. Lecturas No Repetibles (Non-repeatable Reads)

Ocurre cuando una transacción lee el mismo dato dos veces y obtiene valores diferentes.

Ejemplo:
  1. Transacción A lee un saldo
  2. Transacción B modifica y confirma ese saldo
  3. Transacción A lee el mismo saldo de nuevo y obtiene un valor diferente

3. Lecturas Fantasma (Phantom Reads)

Ocurre cuando una transacción obtiene un conjunto diferente de filas en lecturas repetidas.

Ejemplo:
  1. Transacción A lee registros que cumplen una condición
  2. Transacción B inserta nuevos registros que cumplen esa condición
  3. Transacción A lee de nuevo y encuentra registros adicionales

Niveles de Aislamiento

Nivel Dirty Read Non-repeatable Read Phantom Read Uso Típico
READ UNCOMMITTED Posible Posible Posible Reportes no críticos, análisis aproximados
READ COMMITTED Prevenido Posible Posible Operaciones generales de lectura
REPEATABLE READ Prevenido Prevenido Posible Operaciones financieras, balances
SERIALIZABLE Prevenido Prevenido Prevenido Transacciones críticas, datos sensibles

Implementación en SQL

-- Establecer nivel de aislamiento
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- Ejemplo de transacción con nivel específico
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;
    SELECT * FROM cuentas WHERE id_cliente = 100;
    -- ... otras operaciones ...
COMMIT;

1. READ UNCOMMITTED

El nivel más bajo de aislamiento. No impide ningún problema de concurrencia.

-- Ejemplo READ UNCOMMITTED
SET TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
START TRANSACTION;
    SELECT balance FROM cuentas WHERE id = 1;
    -- Puede leer datos no confirmados de otras transacciones
COMMIT;

2. READ COMMITTED

Garantiza que solo se lean datos confirmados.

-- Ejemplo READ COMMITTED
SET TRANSACTION ISOLATION LEVEL READ COMMITTED;
START TRANSACTION;
    SELECT balance FROM cuentas WHERE id = 1;
    -- Esperar un momento
    SELECT balance FROM cuentas WHERE id = 1; -- Podría ser diferente
COMMIT;

3. REPEATABLE READ

Garantiza lecturas consistentes durante toda la transacción.

-- Ejemplo REPEATABLE READ
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
START TRANSACTION;
    SELECT COUNT(*) FROM cuentas WHERE balance > 1000;
    -- Otras transacciones pueden insertar nuevos registros
    SELECT COUNT(*) FROM cuentas WHERE balance > 1000;
COMMIT;

4. SERIALIZABLE

El nivel más alto de aislamiento. Previene todos los problemas de concurrencia.

-- Ejemplo SERIALIZABLE
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
START TRANSACTION;
    SELECT * FROM cuentas WHERE balance > 1000;
    -- Bloquea el rango completo
    -- Otras transacciones no pueden insertar en este rango
COMMIT;

Consideraciones Importantes

  • Mayor nivel de aislamiento = Mayor consistencia pero menor concurrencia
  • Menor nivel de aislamiento = Mayor concurrencia pero posibles inconsistencias
  • Elegir el nivel adecuado según los requerimientos de la aplicación
  • Considerar el impacto en el rendimiento
